## Findings

- Root cause (main `c995b58`): `src/popup.js` `currentOrigin()` reads `activeTab.url` from
  `chrome.tabs.query`. Chrome only fills `tab.url` when the extension has the "tabs" permission,
  "activeTab" (granted on popup click), or host access to that page. The manifest has none of these:
  permissions are `storage` + `declarativeNetRequest`, and host_permissions only cover the list
  hosts. Content-script `matches` do not count as host access for tab URLs. So `tab.url` is
  always missing, `currentOrigin()` returns null, and the button is always disabled with
  "Open a normal http(s) page to allow it."
- "activeTab" would fix it with no install warning, but it is a new manifest permission, which the
  rules forbid. "tabs" is forbidden by the rules and by release-gate.sh.
- PR #11 fix: the popup asks the top-frame content script (`src/cosmetic.js`) for its origin with
  `chrome.tabs.sendMessage(tab.id, {type: "pageOrigin"}, {frameId: 0})`. The approach is right:
  no permission needed, the script already runs on every non-stream http(s) page, and the listener
  sits after the early return for stream hosts only. So it also answers on already-allowed pages
  and when general blocking is off (needed to un-allow, and to show the right "off" text).
- PR #11 gap 1 (test): its test only covers the content-script half. Proof: with #11's
  `cosmetic.js` and main's `popup.js`, #11's test passes and the popup is still broken.
  Nothing tests that the popup asks, uses the answer, and enables the button.
- PR #11 gap 2 (stale tabs): Chrome does not inject declared content scripts into tabs that were
  already open when the extension is installed, updated or reloaded. Those tabs can't answer, so
  the button is greyed out there with a misleading "Open a normal http(s) page" text. Without
  the "scripting" permission we can't inject, so the fix is a hint to reload the page.
- Not fixed (same as main): on Twitch/YouTube/Kick there is no general content script, so the
  popup shows "Open a normal http(s) page..." instead of the stream-site text. The button is
  correctly disabled either way. Fixing it would mean touching stream-site scripts (locked).
- Main has not changed `src/popup.js` or `src/cosmetic.js` since #11's base `aea6f6d`, so this
  branch uses #11's two `src` hunks byte for byte (`git diff origin/claude/festive-gauss-lwkk9t
  -- src/popup.js src/cosmetic.js` is empty). Git merges identical hunks cleanly, so the PRs
  don't fight there. #11's conflicts with main are in README.md only (main rewrote it in #13).
