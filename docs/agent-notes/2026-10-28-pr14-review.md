## Removed comments that should stay

Lines are on main `938699e`.

1. `src/cosmetic.js:75` `// document may be unavailable in unit tests.`
   The PR rewrites it as "document can already be gone." That's wrong: in a real content script `document`
   always exists. The try/catch is there for Deno tests. Proof: with the try removed on main, the suite gives
   266 passed / 9 failed, `ReferenceError: document is not defined` (cosmetic.test.js, popup-allow-page.test.js).
   Keep the original.
2. `src/cosmetic.js:6` `// Same key as popup src/general-settings.js — do not rename without coordinating.`
   This is a cross-file rule, and no test covers it. The new test checks popup.js against general-settings.js.
   `test/cosmetic.test.js:59-60` only pins cosmetic.js's own string literal. So a key rename in
   general-settings.js and popup.js passes every test while cosmetic.js silently drifts. The PR also drops the
   matching line from `src/general-settings.js:4` ("DNR / list / cosmetic agents should use the same keys"), so
   no pointer to cosmetic.js is left. Keep it, or extend the new test to compare cosmetic.js's
   `STORAGE_KEY`/`ALLOWED_ORIGINS_KEY` with general-settings `STORAGE_KEYS`.
3. `src/general/update.js:88` `// Same rules as scripts/pack-filter-lists.py extract_domains().`
   This points at a twin implementation in another language. The new parity test only covers an 18-line fixture,
   so this pointer is what tells an editor to change both. Keep.
4. `src/general/update.js:360` `// Sanity: a refreshed set much smaller than the bundle is a bad download.`
   This explains the magic `0.5` (a guard against cut-off downloads). The error text "refreshed list too small"
   says what, not why. Keep.
5. `src/cosmetic.js:151` `// Back-compat name used by early tests / callers.`
   It says why a one-line alias of `applyState` exists. `test/cosmetic.test.js` still calls `applyEnabled`
   4 times. Keep (or reword to "test/cosmetic.test.js still calls this").
